StampOne Decoder (app_001) - How to run this project
======================================================

WHAT WAS WRONG
--------------
Two dead venvs, both built on other (Linux) machines:
  - The project root ITSELF is a venv (it has pyvenv.cfg, lib/, lib64/,
    include/, share/ sitting right next to manage.py). Its pyvenv.cfg
    points to home = /usr/bin, version 3.10.12.
  - There is also a venv/ subfolder, whose pyvenv.cfg points to
    home = /home/Farhad-buzz/anaconda3/envs/FK/bin, version 3.10.9.
Neither has a python binary that works on this Mac.

Note this is a separate/sibling project to StampOneDec_app_002 (which has
the exact same problem and its own help_running.text) - each needs its
own environment, don't reuse one for the other.

WHAT WAS SET UP
---------------
A new conda env called "stampone_dec_001" (Python 3.10), installed from
this project's own requirements.txt, with ONE change:
  - requirements.txt pins keras==3.1, but that directly conflicts with
    tensorflow==2.15 (which requires keras>=2.15,<2.16 - pip refuses to
    resolve this). settings.py only does `import keras` and prints the
    version - no Keras-3-specific API is used - so the keras==3.1 line
    was dropped and keras 2.15.0 (pulled in automatically by
    tensorflow==2.15) is used instead.
  - Django was pinned to 5.0.4 (matching the "Generated by
    'django-admin startproject' using Django 5.0.4" comment in
    core/settings.py) instead of installing latest unpinned Django.

Everything else installed exactly as pinned: tensorflow==2.15,
bchlib==0.14 (built fine from source on arm64 Mac), opencv-python,
tensorflow_wavelets, onnxruntime, lmdb, qrcode, pyqart, pendulum,
psutil, ninja, imageio, scikit-image, matplotlib, PyWavelets, numpy.

Verified working via: manage.py check, manage.py migrate, and an actual
manage.py runserver request that returned a 200 response.

HOW TO RUN IT
-------------
    cd "/Users/farhad/Documents/VisTeamPro/Programming11/12/StampOne-App/StampOne_de002/StampOneDec_app_001"
    conda activate stampone_dec_001
    python manage.py runserver

Then open http://127.0.0.1:8000/ in a browser.

RECREATING THE ENVIRONMENT ELSEWHERE
-------------------------------------
environment.yml in this folder is a full export of the working
"stampone_dec_001" conda env (already includes the Django==5.0.4 /
keras==2.15.0 fix above). To rebuild it on another machine:

    conda env create -f environment.yml
    conda activate stampone_dec_001

(requirements.txt has a leftover comment
"python manage.py runserver 193.136.230.30:8001" - that was a specific
remote/LAN address the author used before, not needed for local runs.)

THINGS TO KNOW
--------------
- settings.py loads TensorFlow models at Django startup (via
  Tools_stega89_de1/tools_TFLite_decoder.py and DetectionLibs/main.py),
  same as app_002, so `manage.py runserver` will take a few seconds to
  come up while those load.
- settings.py requests tf.device("gpu:1") - on this Mac there's no such
  GPU device, but TensorFlow's default soft device placement silently
  falls back to CPU, so this is not a blocker.
- The two broken venv-like folders (project root itself, and venv/) are
  untouched. The new env lives in conda instead. Safe to clean up later
  if you want.
